     → Deep-Dive Analyst → Ranking → Research Brief (có bằng chứng)

## 5. TIÊU CHÍ KIỂM THỬ & NGHIỆM THU ĐỊNH LƯỢNG

### 5.1. Bốn mức trưởng thành (áp dụng riêng từng module)

- Quy tắc: không công bố mức cao hơn mức thấp nhất của (module + verifier). V2.1 Wave 0–2 tối đa INTEGRATION PASS (read-only).

### 5.2. Tiêu chí nghiệm thu chính từng Wave
- **Wave 0:** quét `v2_1/` = 0 import/path/token trỏ sang V1; oversight chặn **100%** test case nguy hiểm (n=20); audit log verify hash-chain **100%** (n≥100), test sửa ngược phát hiện **100%**; quota accountant sai số ≤5%; baseline đủ 3/3 kênh + top 10 video/kênh (kèm raw JSON).

## 6. CƠ CHẾ GIÁM SÁT ĐỘC LẬP (INDEPENDENT OVERSIGHT)

**Vị trí:** tiến trình/codebase/state RIÊNG (`v2_1/oversight/`), không import module sản xuất, chỉ đọc state các lớp khác. Không được tự sửa code production, tự PUBLIC, tự sửa audit log.

### 6.1. Tám watcher (ánh xạ đúng 8 lĩnh vực chỉ đạo VII)
| ID | Lĩnh vực | Cách kiểm tra độc lập |
|---|---|---|
| W1 | Input data thật/mới/đúng nguồn | Mọi input ngoài có `fetched_at` + `source_url`; dữ liệu quá TTL → flag STALE; spot-check gọi lại API độc lập |
| W2 | Logic chấm điểm KEY + phân tích tăng trưởng | Chạy lại scoring bằng rule engine độc lập; chênh lệch > ngưỡng → flag; trọng số phải có version + history |
| W3 | Chất lượng, nguyên bản, rủi ro nội dung | Originality corpus check (hash script + pHash thumbnail); verdict REVIEW/BLOCKED phải có approval |
| W4 | Danh tính kênh, OAuth, quota, upload/publishing approval | Đối chiếu channel_id đích vs channel_id duyệt (API read-back); token không approval → CRITICAL |
| W5 | Queue, scheduler, chống trùng, lỗi API, trạng thái bất định | Quét idempotency key trùng, stale lock, entry UNKNOWN > T → đánh dấu bất định, retry tối đa 3 |
| W6 | Cron/job lạ, chi phí, tài nguyên, sức khỏe pipeline | Kiểm kê cron định kỳ diff với baseline; CPU >85%/15ph hoặc disk >80% → WARN; mọi chi phí mới → CRITICAL |
| W7 | Thay đổi code/config/model/prompt/chính sách | Manifest sha256 mỗi thư mục; thay đổi không change record → WARN; đổi prompt/model AI bắt buộc có lý do |
| W8 | Tín hiệu bất thường | >K video cùng content-hash/24h; views/subs tăng đột biến lệch baseline; publish vào kênh ngoài registry → CRITICAL + chặn |

### 6.2. Audit log chống sửa ngược
- Append-only JSONL, hash-chain: `hash = sha256(seq|ts|actor|action|subject|detail|prev_hash)`; verifier chạy mỗi giờ; đứt chuỗi → CRITICAL + dừng mọi tác vụ ghi.
- Neo 24h: ghi hash cuối ngày ra 2 nơi độc lập (1 ngoài VM). File log cũ chmod chỉ-đọc sau xoay vòng.

### 6.3. Cảnh báo 3 mức (kế thừa dedup + cooldown V1)
- **CRITICAL** (chặn + báo ngay): publish/upload nhầm kênh; publish chưa duyệt; audit đứt chain; V2.1 ghi vào V1; token không approval; quota ≥95%; publish vào kênh ngoài registry; phát sinh chi phí.
- **WARN** (xử lý trong ngày): input STALE; scoring lệch; fact chưa verify vượt ngưỡng; cron lạ; đổi code không record; trùng lặp nội dung; QC REVIEW tồn >48h; VM quá tải.
- **INFO** (digest hằng ngày): milestone, weight tuning + rollback pointer, snapshot V1 copy.

### 6.4. Interlock / Kill-switch (cơ chế kỹ thuật)
Mọi thao tác gây tác động (upload, publish, set-thumbnail, comment, playlist write, token write) **bắt buộc** qua `interlock.guard(action, ctx)`, kiểm tra theo thứ tự, **fail-closed**:
1. File `state/KILL` tồn tại → DENY toàn cục. 2. Channel breaker tripped → DENY kênh đó. 3. Action allowlist (`auto_public: false` → mọi publish DENY đến khi duyệt). 4. Identity match (lệch → DENY + C1). 5. Approval (publish cần `approval_id` hợp lệ, thiếu → DENY + C2). 6. Quota còn budget.
- Mọi DENY ghi audit log + alert; không có đường vòng (chỉ module distribution được chứa API call, và mọi call nằm sau guard).
- Kích hoạt KILL: watcher tự tạo khi gặp C1/C2/C7, hoặc sếp/parent tạo tay. Gỡ KILL chỉ bằng lệnh có chữ ký trong audit log (không tự gỡ).

### 6.5. Escalation 4 bậc
1. Auto-retry lỗi transient (tối đa 3, backoff). 2. WARN → digest hằng ngày cho parent. 3. CRITICAL → block + báo parent kèm evidence bundle. 4. **Escalate sếp** khi: sự cố bảo mật, rủi ro pháp lý/bản quyền, chi phí, thay đổi không đảo ngược, KILL kích hoạt — theo format 5 điểm: (1) chuyện gì, (2) bằng chứng, (3) ảnh hưởng, (4) hệ thống đã tự chặn gì, (5) cần sếp quyết 1 hành động cụ thể.

### 6.6. Bản tối thiểu Wave 0 (5 thành phần)
O0-AUDIT (log + verify) · O0-INTERLOCK (default-deny, `auto_public: false`) · O0-IDENTITY (verify read-only) · O0-CRON-WATCH (baseline + diff hằng giờ) · O0-DIGEST (báo cáo hằng ngày). Tiêu chí qua Wave 0: 5 thành phần INTEGRATION PASS + chạy ổn định 7 ngày.
